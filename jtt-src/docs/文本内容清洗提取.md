## 一、赛题核心逻辑（整体思路）

> **新岗位发现 → 已有岗位能力动态更新 → 能力图谱展示 → 人岗匹配诊断 → 改进建议/学习路径推荐**

- 不仅要爬取招聘网站数据，还要参考**行业报告、调研数据**

- 新兴岗位示例：

    - Prompt Engineering提示工程 → Context Engineering上下文工程 → Harness Engineering驾驭工程

    - 具身智能相关岗位

- 既有岗位（如Java开发工程师）能力要求正在变化：

    - 不仅要懂Java，还要会RAG、AI能力、全栈技能等。

- 现有的岗位名称的多种叫法：

    - 定义一个大框架，根据技能不断地从小到大进行岗位分类

- **数据问题**：招聘数据存在滞后性、抄袭、假数据等问题，需要在方案中体现应对策略（即使实践中未完全解决，答辩时必须“答得好”）。


---

## 二、核心功能要求（四个模块）

与赛题文档一致，包括：

1. **新岗位识别与定义**

    - 市面上的新技能，根据技能的普及程度定义新的岗位

    - 生成岗位名称、核心职责、必备技能、加分技能、典型应用场景

    - 支持人工优化与动态更新

2. **既有岗位能力动态更新**

    - 针对现有岗位（如Java开发），识别能力要求变化

    - 明确标注新增、删除、修改的能力项，提供数据源和更新说明

3. **全景图谱可视化**

    - 展示岗位与技能点级别的关系

    - 支持按技术栈、级别（初级/中级/高级）切换视图

    - 支持版本化管理和时间维度查询：要设计时序图谱存储方案，支持”某技能在过去N个月的需求变化”等查询

4. **人岗匹配度诊断**

    - 简历解析（PDF/Word），准确率≥90%

    - 多维度匹配分析，提供**改进建议**与**学习路径规划**

    - 岗位图谱+匹配报告


> 注：讲解人提到，该赛题与另一个“资源推荐”赛题有延续性——匹配出差距后，可去另一个载体找学习资源或做推荐。

## 三、创新性要求（答辩加分点）

- **多源异构数据交叉验证与融合机制**：解决时滞、噪声、抄袭问题

- 讲解人特别强调：

    - 985/211院校在**理论性、技术战略、论文发表**方面有优势

    - 我们（普通院校）应更注重**工程实现、功能完整性、应用场景落地**

## 四、可验证性要求（硬性指标）

- **测试方案完整**：至少100条岗位JD及测试用例

- **三项准确率 ≥ 90%**：

    - JD解析准确率

    - 简历提取准确率

    - 人岗匹配准确率

- 需要明确**90%如何衡量**（后续会提供评分策略文档）

## 六、作品评选标准（100分制）

|维度|分值|要点|
|---|---|---|
|**完整性**|30分|全流程闭环（数据采集→岗位发现→图谱更新→可视化→简历解析→匹配诊断），系统可部署运行|
|**技术创新性**|25分|突破性方案，幻觉防控，数据融合机制|
|**用户体验**|15分|界面友好，图谱交互流畅，差距分析清晰|
|**实用价值**|30分|测试方案完整（≥100条JD），三项准确率≥90%，方案可迁移，非写死|

- **实用价值高分关键**：选择具体行业（如IT互联网）深入做，准备真实数据集（1000+岗位、500+简历样本），提供Docker一键部署。

## 七、赛题本质与常见误区（讲解人强调）

- **本质**：数据驱动的智能决策系统，而非单纯的知识图谱项目

- **常见误区**：

    - 只爬单一招聘网站

    - 忽略数据清洗、时效性标注、质量评估

    - 未处理实体消歧（如“Java开发”=“Java工程师”）


---

## 八、技术推荐（简要提及）

- 数据采集：Scrapy + Playwright

- 存储：MySQL + Elasticsearch

- NLP：HanLP + 讯飞星火API

- 知识图谱：Neo4j

- 可视化：AntV G6 / ECharts

- RAG：LangChain + ChromaDB

- 后端：FastAPI / Flask

- 前端：Vue 3

- 简历解析：讯飞OCR + 自定义NER


> 讲解人建议：优先使用讯飞相关工具（满足赛题要求），通用部分可自由选型。
