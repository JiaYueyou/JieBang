## 原题目要求：

> 二是如何解决招聘数据中的“时滞”、“噪声”与“抄袭”问题，并通过技术手段有效防控AI生成内容 “幻觉”的产生，提升图谱构建的科学性；


### 涉及问题：

 - “**时滞**”，“**噪声**”和“**抄袭**”体现在哪些方面？具体表现形式如何？
**理解**：岗位发布时间久，JD描述很多对应岗位不需要的技能，JD重复多次出现。
**解决方案**：及时更新获取新岗位数据，检查和判断与岗位不匹配的技能是为新加技能还是无需技能，JD多次出现根据描述内容和岗位来源进行相似度匹配，在数据处理部分做去重工作。

 - “幻觉”问题具体表现在哪些方面？可能会编造什么内容？
 **理解**：只要涉及Agent的部分，都可能引发幻觉问题，对于JD生成，我们避免生成与目标岗位不匹配的数据，薪资，部门等信息。
 **解决方案**：使用正则和结构化输出字段进行输出约束，避免生成不匹配和多余字段信息。

 - RAG用于语义相似度检索，又能使用在哪些地方？哪些部分需要知识库？需要构建什么样的知识库？

### 本项目架构涉及的Agent

| 模块                                | 功能                                                       | 可能幻觉风险                                                                                       |
| --------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **LLM Provider（结构化输出）**           | DeepSeek 结构化 JSON 调用，temperature=0，注入 JSON Schema，失败重试一次 | Schema 约束只保证格式，不保证内容真实；LLM 仍可在合法 JSON 内编造字段值                                                 |
| **Skill Extraction Agent**        | 在规则抽取后，调用 LLM 补充“规则未识别的明确技能”                             | LLM 补充的新技能未与词典/原文做二次校验，可直接进入 `JobSkillFact`                                                  |
| **Skill Extraction Prompt**       | 要求“只输出文本中明确出现且可验证的技术技能，不得推测”                             | 仅有软提示，无事实约束机制；模型对“明确出现”理解不一                                                                  |
| **Graph Enrichment Agent（L4/L5）** | 为已验证 L3 技能补全技术点/知识点                                      | 可生成与 evidence 文本语义不符的 L4/L5 节点                                                               |
| **Graph Enrichment Prompt**       | 要求“每个技术点必须能被输入原文直接支持，引用至少两个不同平台来源”                       | 无自动语义校验，source_ids 可被模型任意关联                                                                  |
| **L45 Standalone Agent**          | 独立 DeepSeek 调用生成 L4/L5，temperature=0.1                   | 输出不强制绑定 source_id；`verify.py` 的置信度只按来源数计算，不看内容                                               |
| **JD Generation Agent**           | 根据岗位名称/技能输入生成可编辑 JD 草稿                                   | `standardized_title` 自由生成；skills 不受词典约束；可生成未经验证的“常见”技能                                       |
| **JD Generation Prompt**          | 禁止虚构薪资、福利、学历、工作年限                                        | 对“技能是否真实存在/是否匹配岗位”无外部校验                                                                      |
| **Career Planning Agent**         | 基于简历与目标岗位差距生成学习路径                                        | `ResumeProfile` 中 current_role/years_experience/education 可由 LLM 自由推断；suggested_project 自由生成 |
| **Career Planning Prompt**        | 要求学习步骤必须对应 candidate.gaps，禁止重复 verified_skills           | 无法防止模型为同一 gap 编造不同名称；resources 仅口头约束                                                         |
| **Match Explanation Agent**       | 解释确定性匹配快照                                                | evidence_id 被后验过滤，但 explanation 文本与 evidence_text 的语义一致性未校验                                  |
| **Import Service（数据导入）**          | 幂等导入 JD，内容指纹去重，交叉验证技能事实                                  | 交叉验证只要求 skill 跨源出现 ≥2 次，不保证该技能真属于该岗位                                                         |
| **Rule Skill Extractor**          | 基于技能词典扫描 JD 文本，生成 `JobSkillFact`                         | 软技能/噪声词可能命中；非技术岗位文本中技术词误识别无法自动剔除                                                             |
| **Graph Service（同步与补全）**          | L1-L3 确定性构图，L4/L5 候选验证                                   | L1-L3 依赖 `verification_status=verified`，但验证规则未考虑时间衰减；L4/L5 过滤只看 source_id 存在性和置信度数值          |
| **Data Analysis 清洗流水线**           | URL/指纹/标题+公司相似度三级去重                                      | 未对 JD 正文做 MinHash/SimHash 近重复检测；未做时滞/可信度评分                                                   |
| **Job Standardizer**              | 规则清洗标题、推断级别/技术栈                                          | 硬编码城市列表和噪声词，对新招聘平台/新工种覆盖不足                                                                   |
| **Skill Dictionary**              | 标准 IT 技能词典与别名                                            | 词表有限，LLM 补充的新技能可能不在词典中，导致图谱节点不可控                                                             |

### 本项目Agent的分层设计方案

#### 1. 数据层Agent：先把“时滞、噪声、抄袭”挡在图谱外

#### 2.规则层Agent：L1-L3 坚持“无 LLM 生成”

#### 3. 生成层Agent：Agent 输出必须经过“证据绑定 + 语义校验”

#### 4. 应用层Agent：Agent 只生成“可编辑草稿”，不直接发布



>重点在于题目解析，三个问题和幻觉的具体体现是什么样？没有确定问题的情况和状态没办法设计对应的解决方案。
