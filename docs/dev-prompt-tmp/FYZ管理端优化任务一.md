# 二、任务一：优化岗位数据处理链路

## 当前问题

当前岗位数据从采集到知识图谱展示的整体链路包括：

数据获取 → 数据清洗 → 数据标准化 → 数据处理 → 数据入库 → 知识图谱构建与展示。

目前主要存在以下问题：

* 部分岗位名称没有被正确标准化；
* 同一岗位存在多个相近或重复名称；
* 岗位名称、技能、行业、公司等字段中可能存在噪声数据；
* 部分岗位与技能之间的关联不准确；
* 知识图谱中展示的节点和关系相关性较低；
* 清洗、标准化和图谱构建过程中缺少清晰的数据质量校验机制。

## 优化目标

请分析现有的数据处理代码，并重点优化以下环节：

### 1. 数据获取

* 检查不同数据源的数据结构和字段映射是否一致；
* 增加必要的数据完整性校验；
* 对缺失字段、异常字段和重复记录进行标记；
* 避免低质量数据直接进入后续处理流程。

### 2. 数据清洗

* 清理 HTML 标签、特殊字符、无意义文本和异常空格；
* 统一岗位名称、技能名称、公司名称和行业名称的格式；
* 对重复岗位、相似岗位和重复技能进行去重；
* 保留原始数据和清洗后数据，确保处理过程可追溯。

### 3. 岗位标准化

重点检查岗位标准化逻辑，提升标准岗位映射的准确率。

需要考虑：

* 岗位别名；
* 中英文岗位名称；
* 缩写；
* 同义词；
* 岗位等级，例如初级、中级、高级、资深；
* 岗位方向，例如 Java 开发、后端开发、服务端开发；
* 模糊匹配导致的错误映射；
* 无法确定时是否应进入人工审核或待确认队列。

标准化结果至少应包含：

* 原始岗位名称；
* 清洗后的岗位名称；
* 标准岗位名称；
* 标准岗位 ID；
* 匹配方式；
* 匹配置信度；
* 是否需要人工审核；
* 标准化依据或解释。

禁止在低置信度情况下强制映射到某个标准岗位。

### 4. 岗位与技能关系处理

* 检查技能抽取结果是否真正来源于岗位描述；
* 降低无关技能、泛化技能和错误技能关系的权重；
* 对岗位与技能之间的关系增加来源、置信度、出现次数或证据字段；
* 优先展示高相关、高置信度的岗位—技能关系；
* 避免将所有抽取出的技能直接作为强关系写入图谱。

### 5. 数据质量评估

为数据处理链路增加可量化的质量指标，例如：

* 岗位标准化成功率；
* 高置信度匹配率；
* 待人工审核数量；
* 重复数据比例；
* 无效数据比例；
* 岗位—技能关系平均置信度；
* 图谱节点孤立率；
* 图谱关系异常率。

请尽量复用现有数据模型、处理流程和服务，不要无必要地重新设计整套数据架构。

# 三、任务二：优化技能知识图谱

## 当前问题

当前技能知识图谱存在以下问题：

* 页面初始化时读取全部节点和关系，接口响应时间较长；
* 图谱数据量较大时页面明显卡顿；
* 点击层级筛选按钮后，无法正确显示对应层级的数据；
* 层级筛选可能只修改前端状态，但没有真正过滤数据；
* 节点和标签存在较多重叠；
* 图谱布局不稳定；
* 节点拖拽体验较差；
* 无法方便地平移、缩放和查看局部图谱；
* 图谱缺少渐进式加载和局部探索能力。

## 优化目标

### 1. 后端查询性能

禁止在页面首次加载时直接返回全部节点和全部关系。

请根据现有数据库和图谱结构，设计合理的数据加载方式，例如：

* 首屏只加载核心节点；
* 按岗位、技能类别或层级查询；
* 按节点向外扩展一层或多层；
* 分页或限制返回数量；
* 根据当前视口或筛选条件加载数据；
* 对常用查询增加缓存；
* 优化 Neo4j 查询语句和索引；
* 避免重复查询和 N+1 查询；
* 设置合理的最大节点数和最大关系数。

后端接口应支持必要的参数，例如：

* `level`：图谱层级；
* `root_id`：中心节点；
* `depth`：向外扩展深度；
* `node_type`：节点类型；
* `keyword`：搜索关键词；
* `limit`：最大节点数量；
* `min_confidence`：最低关系置信度。

### 2. 层级筛选修复

检查层级按钮从前端到后端的完整调用链路，包括：

层级按钮 → 状态更新 → 请求参数 → 后端接口 → 图数据库查询 → 返回数据 → 图谱重新渲染。

确保：

* 点击不同层级按钮后能够正确获取对应层级的数据；
* 不同层级的数据范围具有明显区别；
* 切换层级时旧数据能够正确清理或合并；
* 加载过程有明确的 loading 状态；
* 接口失败时有错误提示；
* 无数据时显示空状态，而不是空白页面；
* 快速连续点击时不会出现请求竞态和数据覆盖问题。

### 3. 图谱布局与重叠优化

根据当前图谱技术栈，合理调整：

* 节点间距；
* 斥力；
* 连线长度；
* 碰撞检测；
* 标签显示策略；
* 节点大小；
* 节点类型颜色或图标；
* 缩放比例；
* 聚类或分组布局；
* 布局完成后的稳定机制。

应尽量减少：

* 节点重叠；
* 标签重叠；
* 连线交叉；
* 图谱持续抖动；
* 页面重新渲染造成的布局重置。

数据量较大时，可以采用：

* 标签按缩放级别显示；
* 非核心节点弱化；
* 同类节点聚类；
* 局部展开；
* 按需渲染；
* 限制首屏节点数量。

### 4. 图谱交互优化

需要支持并检查以下交互：

* 鼠标拖拽节点；
* 拖拽空白区域平移画布；
* 鼠标滚轮缩放；
* 双击或点击节点展开相邻节点；
* 点击节点查看详细信息；
* 节点搜索与定位；
* 重置视图；
* 自动适应画布；
* 返回上一级；
* 重新执行布局；
* 锁定或释放节点位置。

拖拽节点时，不应导致整个图谱重新初始化。

### 5. 图谱状态管理

请检查当前图谱是否因为 React/Vue 状态更新而频繁销毁和重新创建实例。

优化要求：

* 图谱实例应尽可能复用；
* 数据变化时优先执行增量更新；
* 避免无关状态变化触发整个图谱重新渲染；
* 正确销毁事件监听器和图谱实例；
* 避免内存泄漏；
* 搜索、筛选、层级和展开状态应保持一致。

# 四、任务三：重新设计人才匹配中的简历上传区域

## 当前问题

人才匹配页面中的简历上传区域视觉效果较差，存在以下问题：

* 上传组件没有居中；
* 页面左右或上下布局不对称；
* 上传区域尺寸和间距不协调；
* 页面缺少明确的视觉层级；
* 上传状态、文件信息和操作按钮展示不清晰；
* 与管理端其他页面的设计风格不统一。

## 设计要求

请调用并遵循项目中的 **frontend-design Skill**，重新设计人才匹配页面的简历上传区域。

设计目标：

* 整体内容水平居中；
* 页面布局对称、整洁；
* 上传卡片具有合理的最大宽度；
* 上下留白和组件间距协调；
* 保持管理端现有视觉风格；
* 不要使用过度花哨的渐变、阴影或动画；
* 桌面端和常见笔记本分辨率下都应正常显示；
* 在较小屏幕下能够自适应。

上传区域建议包含：

* 页面标题；
* 简短的功能说明；
* 居中的拖拽上传区域；
* 支持格式和文件大小提示；
* 已选择文件的信息；
* 上传进度；
* 上传成功状态；
* 上传失败状态；
* 删除或重新选择按钮；
* 开始分析或开始匹配按钮；
* 分析过程中的 loading 状态；
* 必要的错误提示。

需要确保上传区域在以下状态下都具有完整样式：

1. 未选择文件；
2. 拖拽文件悬停；
3. 已选择文件；
4. 正在上传；
5. 上传成功；
6. 上传失败；
7. 正在解析简历；
8. 解析完成。

不要只修改 CSS，应同时检查组件结构、状态管理、事件处理和接口调用。
