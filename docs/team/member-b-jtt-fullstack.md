## 1. 职责

负责 `jtt-src/frontend` 和求职者场景对应的后端接口：

- 岗位浏览、详情、收藏和快速匹配；
- 简历上传、解析、编辑、版本和定向优化；
- 人岗匹配结果、差距说明、学习路径和个人中心；
- JTT API 请求层、状态管理、上传安全和错误恢复。

前后端由同一人完成，但 Agent 推理内核由成员 C 提供，图谱查询由成员 E 提供。

## 2. 当前基线

- 已有岗位、简历、匹配、收藏、学习路径和个人中心页面骨架。
- 已有 `positions.ts`、`resume.ts`、`match.ts`、`tailor.ts` 等请求模块。
- 部分页面仍依赖 mock/MSW，真实求职者后端接口尚不完整。

## 4. 4 周 MVP

### 第 1 周：真实认证与岗位

- 接入统一 JWT 登录和注册。
- 岗位列表、搜索、筛选和详情使用真实后端。
- 清理关键流程中的硬编码 ID 和伪成功状态。

### 第 2 周：简历

- 建立简历上传、解析状态、失败重试和结果编辑 API。
- 支持 PDF/Word 的类型、大小和异常提示。
- 保存结构化教育、经历、项目和技能，不把原始文件暴露为公共 URL。

### 第 3 周：匹配与解释

- 创建匹配任务并展示总分、维度分、证据、差距和不确定性。
- 区分事实评分、模型解释和建议，禁止把生成建议伪装为简历事实。
- 支持从岗位详情或简历详情发起匹配。

### 第 4 周：收藏与学习路径

- 收藏岗位和结果持久化，不再只存 localStorage。
- 接入学习路径/转岗规划 MVP。
- 跑通“登录 → 上传简历 → 选择岗位 → 匹配 → 查看建议”演示闭环。

## 5. 后 8 周优化

- W5-W6：多简历版本、历史匹配、定向简历生成和差异确认。
- W7-W8：收藏同步、岗位推荐、学习资源和路径进度。
- W9-W10：上传性能、移动端、可访问性和隐私删除能力。
- W11-W12：端到端回归、演示账号、空数据和模型不可用降级体验。

## 6. 交付与验收

- 所有核心页面在关闭 MSW 后可使用真实后端。
- 上传、解析、匹配均有可查询任务状态和失败原因。
- 匹配解释能引用简历片段、岗位要求或图谱证据。
- 用户可以删除简历及相关敏感数据。

## 9. 主要风险

- mock 与真实接口并存导致错误被遮蔽；
- 上传文件泄露、类型欺骗或过大；
- 匹配分数无证据、不同页面计算口径不一致；
- 前端自行解析模型自由文本而不是结构化 Schema。
